# A guided LUCH workflow: from request to a result you can inspect

LUCH is designed to help an AI move from an answer to bounded work with resources the user has selected.

## 1. Name the outcome

Start with the result you want, not a tool name.

> “Compare the information on these public pages and prepare a short brief with direct source links.”

## 2. Select the resources

The AI checks which LUCH tools are actually exposed to the current account. It uses an isolated server browser for supported public-page work, or a specifically authorized file/device/server route when the task needs one.

## 3. Do the smallest useful piece of work

Read first. Compare the material. If the task requires a change, identify the exact target and permission before writing or submitting anything.

## 4. Return with evidence

A useful result tells you:
- what was actually read or changed;
- which sources support the conclusion;
- which checks were performed;
- what remains uncertain;
- what decision is yours to make next.

## 5. Keep the human in control

Review a draft before it is saved or published. Confirm external submissions and irreversible changes separately. Release temporary browser sessions when the task is complete.

---

This is a **guided description of the product workflow**, not a fabricated customer story or a claim that a fresh user has passed onboarding. The real founder-environment LUCH case is documented in the [platform repository](https://github.com/lenar2/luch/blob/main/docs/REAL_WORK.md). Host access and current tool availability are determined by the live account and session.
