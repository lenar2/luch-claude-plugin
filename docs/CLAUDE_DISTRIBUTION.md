# Claude distribution: two honest integration boundaries

## 1. LUCH Full — direct connection

The root plugin and its .mcp.json still point to the existing complete LUCH Core MCP service. Full LUCH supports browser and computer actions where the owner has authorized them. Those actions can include clicks and typing by AI; user confirmation is not baked into this package. The Claude host may independently require approval. We do not circumvent provider controls.

The existing submission was refused for logged-in arbitrary-site browser automation and open-ended desktop/phone/website automation. Full LUCH must not be rebranded as directory-compatible while these capabilities remain exposed.

## 2. LUCH Projects — directory candidate

The separate directory/ package is a named GitHub project integration. The directory-gateway/ code enforces the GitHub-only tool set for every call; it does not merely hide tools in the plugin description. It supports authorized GitHub write operations including issues and file changes without a manual last-click step imposed by LUCH.

Directory listing is CONDITIONAL: separate HTTPS service, OAuth audience isolation, independent end-to-end tests, tool schemas, test account and a provider approval are still necessary. Do not submit a non-deployed URL or promise publication.

## Non-negotiable quality gates

- Full LUCH Core remains unchanged and is not proxied through the directory package to expose arbitrary tools.
- Unauthorized tools/call and discovery of browser, local desktop, shell and phone tools must be denied at the backend.
- User identity, tenant isolation, OAuth scopes and revocation are independently tested.
- GitHub writes finish and produce verified receipts through actual permitted API operations.
- A new standalone source folder is selected in the directory portal after the service is real.
- Resubmit only after the two current blocking findings have been genuinely removed from the submitted plugin's reachable capabilities.
